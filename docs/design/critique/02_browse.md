# 02 Browse 画面（S1 ホーム / 問題一覧 / S2 問題詳細 / S6 履歴）批評と再設計提案

- 対象: `/`・`/problems`・`/problems/[id]`・`/sessions`
- 根拠の表記: ソースは `apps/web/src/` からの相対パス `file:line`、スクショは `design/before/<名前>.png`
- 参照: 要件 04 §5–§8、DADS react-components（MIT）と design-tokens 2.1.0

## 0. 結論（先に）

1. **今いちばん重いのは見た目ではなく「壊れている所」**です。モバイルの問題一覧でタイトルが 1 文字まで潰れます。キーボード一覧の ARIA が不正です。フォーカス表示も独自定義がありません。DADS を当てる前にこの 3 つを直します。
2. **ホームが「次に何をやるか」に答えていません**。最上段にカテゴリが 9 枚並び、そのうち 3 枚は 0 問です。前回の `next_practice` は履歴ページの灰色の 1 行に埋もれています。
3. **S2 で問題文を全文見せるのは要件の思想と矛盾します**。04 §6.1 は「初見で要件を読む練習」を理由にホームで問題文を隠しています。それなのに S2 では、時計が動く前にじっくり読めてしまいます。R1「要件確認」の練習効果が落ちるので、決定が必要です（§2.3）。
4. DADS から取り入れるのは**フォーカスリング、フォーム部品の輪郭とサイズ、Table/ResourceList の行パターン、Dl、Breadcrumbs**です。**色（ダークトークンがない）、16px 基準の余白、SearchBox の送信ボタン、ChipLabel をフィルタに使うこと**はそのまま入れません（§5）。

## 2. ユーザの目的から逆算した改善案

ユーザは 1 人、目的は「ライブコーディング面接で説明しながら書けるようになる」。Browse 画面がやることは 4 つしかない。
**①次の 1 本を決める → ②条件を確かめて安心して始める → ③終わったら何が伸びて何が残ったかを知る → ①に戻る**。

### 2.1 ホーム = 「次の 1 本を決める画面」にする（Yes）

ただし盛りすぎない。「今日の 1 問（弱点タグから選出）」には落とし穴がある。`next_practice` は軸単位（例: R5 テスト意識）で、**問題とテスト意識を結ぶデータは存在しない**。「この問題でテスト意識が鍛えられる」と言い切ると嘘になる。そこで v1 は次の正直な構成にする。

1. **続きがあるとき（最優先・条件付き表示）**: status が `recording` / `finalizing` / `failed` / `recovering` のセッション。「中断されたセッションがあります — 部分データでレビュー / 破棄」。DADS NotificationBanner（warning）相当を 1 枚だけ出す。
2. **次に意識すること**: 最新評価の `next_practice` を最大 3 件（FR-U-16）。軸名＋行動文で表示する。**問題の推薦とは分けて**書く。
3. **次の 1 問（候補 3 つ）**: 推薦理由をラベルで明示する。「前回の同カテゴリで未着手」「前回と同じ問題を再挑戦」「Pixiv 形式 20 分」。推薦ロジックは決定的なルールにし、理由を必ず表示する（§7 原則 5「評価は根拠付き」と同じ姿勢）。
4. **カテゴリから探す**: 二次導線に格下げする。0 問カテゴリは**非表示か無効表示**にする（「準備中 · 0 問」、リンクにしない）。進捗は「挑戦済み 3 / 7」で示す。
5. **最近のセッション**: 3 件まで。状態は日本語の ChipLabel、右に「レビュー」。

初回（セッション 0 件）は 1→3 を「はじめの 1 問」1 枚に置き換える（fe-0001 Pixiv 形式を推奨）。あわせて、ローカル完結であること（録画・ログは `data/` に残り外へ出ない）を 2 行の文で説明する。

### 2.2 問題一覧 = 「絞って、比べて、1 本選ぶ」

- **フィルタは 2 種類に分ける**。頻繁に使うもの（カテゴリ・難易度・時間・状態）は**チェックボックス群**で複数選択可、件数付き。たまに使うもの（言語・NFR・tier）は **Select**。select の中にラベルを埋め込むのはやめ、ラベルは外に出す。
- **状態フィルタを新設**: 未着手 / 挑戦済み / 要再挑戦（最新評価で総合 < 3 など、閾値は明示）。04 §6.1 の「未着手・再挑戦」に対応する。
- **適用中の条件を一覧の直上に要約**する: 「12 問 / 27 問 · FE, L2, 未着手 ［すべて解除］」。件数は `aria-live="polite"`。
- **表現は画面幅で切り替える**。≥768 は列見出し付きのテーブル（行全体が 1 リンク）、<768 は 2 行の ResourceList（1 行目タイトル、2 行目にメタ情報のチップ）。
- 列は「タイトル（ID は下段に小さく）/ カテゴリ / 難易度 / 時間 / 言語 / 自分の記録（最終挑戦日・ベスト）」。**自分の記録列が一覧の新しい価値**になる。
- 既定で `draft` は隠す（「下書きを含める」チェックで表示）。core と generated は混在させてよいが、generated にはテキスト付きチップを付ける。
- キーボード: `/`・`j/k`・`Enter` は維持。カーソルは**実フォーカスを行リンクに移す**方式（roving tabindex）に変え、listbox/option ロールはやめて素の `<table>` / `<ul>` にする。矢印キーの横取りもやめる（j/k だけにする。矢印はスクロールに返す）。

### 2.3 問題詳細（S2）= 「開始前の不安を減らす」

不安の中身は「何が起きるか分からない」「条件を取り違える」「戻れない」の 3 つ。対策は次の 3 つ。

- **「この練習の流れ」を本文の最上段に置く**。①開始で録画と編集ログの記録が始まる ②制限時間 20 分で、残り 5 分で色が変わる ③終了ボタンか時間切れで終わる ④レビューで面接官メモ・隠しテスト・解説が開く。DADS StepNavigation 風の番号付きリストで示す（操作できるステッパーにはしない）。
- **条件は 1 か所にまとめる**（DADS Dl）。時間・面接官モード・質問可否・Web 検索・判定方式（「ブラウザで動作確認」のように人の言葉で）・スターター。制約本文と重複する項目は、本文から外すか dl を正とする。
- **選ぶものは開始ボタンの直上に集める**: 言語（4 つ以下なら Radio、5 つ以上なら Select）、面接官モード（Radio: 無言 / 追問あり）。
- **開始ボタンは 1 つ、大きく、自動フォーカス**。Enter で開始する理由を「フォーカス中のボタンを押す」ことに寄せ、グローバル keydown を廃止する。キーボード 1 回で開始できる点は変わらない。
- **この問題の前回記録**: 前回の日時と総合、前回の `next_practice` を 1 行（「前回の課題: 区切りごとに実行する」）。再挑戦時の不安を「何に気を付ければいいか」に変換する。
- **問題文の扱い（要決定）**:
  - 案 A（推奨）: 既定は閉じた Disclosure「問題文を開始前に読む（初見での要件確認の練習にはなりません）」。開くと、その旨をセッションのメタデータに記録し、レビューで R1 の解釈に添える。
  - 案 B: 現状どおり全文表示。そのかわり 04 §6.1 の「初見性」の主張は取り下げる。
  - 実面接（Pixiv 形式）では問題提示と同時に時計が動く。A のほうが本番再現性（原則 4）に沿う。

### 2.4 履歴（S6）= 「成長と、次の一手が見える」

- **最上段に「次にやること」**（最新評価の `next_practice` 最大 3 件、各項目に根拠セッションへのリンク）。ホームと同じ内容を出すことに問題はない。履歴から来た人にも必要になる。
- **要約の数字は 3 つまで**: 練習回数・合計練習時間・評価済み回数。連続日数やバッジは出さない（§7.4）。
- **推移**: 5 件未満は現行の文章表示を維持する（良い判断）。5 件以上は 8 軸スパークラインに加えて、**発話×コードの固有指標**（無言時間比率・初回編集までの時間、FR-U-18）を。総合点は小さく添えるだけにする。
- **カテゴリ×難易度ヒートマップ**（FR-U-18）は、セル値を「挑戦回数」と「最新総合」で切り替えられるようにする。色だけに頼らず数値を併記する。セッション 5 件未満では出さない。
- **セッション表**: 「問題単位でまとめる / 時系列」を切り替えられるようにする（DADS Tab ではなくセグメント 2 択で十分）。問題単位では、行を展開すると各回と前回比（+0.4）が見える。未完了セッションは表から分け、「未完了 2 件」として上に出し、操作（部分レビュー・破棄）を付ける。
- 列: 問題 / 日時 / 時間 / 状態（ChipLabel）/ 総合 / 操作（レビュー・再挑戦をボタン化）。「評価件数」列はやめ、再評価が複数ある時だけ「評価 2 回」を補足する。

## 4. 共通レイアウト

```
┌─────────────────────────────────────────────────────────────────────────┐
│ [本文へスキップ]                                                         │ ← フォーカス時のみ表示
│ LCI  ライブコーディング面接トレーナー   ホーム  問題  履歴     テーマ (自動|明|暗) │
└─────────────────────────────────────────────────────────────────────────┘
```

- **ヘッダ**: 高さ 56px、下に 1px の境界線。左はアプリ名（ホームへのリンク。サブ名は ≥1024 のみ表示）。中央寄せせず、ナビはアプリ名の右に置く。現在地は `aria-current="page"` と下線 3px で示す（DADS HorizontalMenu 相当の見た目だけ借りる）。右にテーマ切替。
- **テーマ切替は 3 状態（自動 / ライト / ダーク）**。FR-U-21 の「OS 追従＋手動切替」をそのまま UI にする。`localStorage` に保存し、`<html data-theme>` へ反映する。読み込み時のちらつきを防ぐため、`<head>` のインラインスクリプトで先に当てる。**面接画面（S3）ではヘッダごと出さない**（§7.2 セッション中はテーマ切替を無効に）。
- <768: ナビは 3 項目しかないので、ハンバーガーにはせず**横並びのまま**にする（アプリ名を「LCI」だけにすれば 360px に収まる）。DADS HamburgerMenuButton は不要。
- **ページ幅**: 全 Browse 画面でコンテナを統一する（max 1200px、左右ガター 16 / 24 / 32px を <768 / 768–1279 / ≥1280 で）。読み物の列（問題詳細の本文）だけは内側で max 720px（日本語 16px で約 40 字/行）に制限する。左端を画面間で揃えるのが目的。
- **パンくず（DADS Breadcrumbs）**: 階層 2 以上の画面（問題詳細・セッションレビュー）**だけ**に置く。トップレベル 3 画面はヘッダが現在地を示すので、パンくずは重複になる。最後の項目は `aria-current="page"`、区切りはシェブロン（aria-hidden）。
- **見出しの規約**: h1 = 24px Bold（ページ名）/ h2 = 20px Bold（セクション）/ h3 = 16px Bold。muted 色を見出しに使わない。h2 の右には「すべて →」リンクを置ける。
- **本文サイズ**: Browse は 16px / 行間 1.7 を基本とし、表などの密な部分は 14px / 1.5。**12px 未満は使わない**（11px を廃止）。要件 §7.1 の「本文 14px」は面接画面向けとして残す。
- **フォーカス**: DADS 方式（黒 4px アウトライン＋黄 2px リング、offset 2px）を全インタラクティブ要素に。ダークでは白アウトライン＋黄リングに反転させる。

## 5. DADS を当てはめるべきでない箇所（批判的に）

| 対象 | 判断 | 理由 |
|---|---|---|
| **配色トークン全体** | 部分採用 | DADS 2.1.0 の tokens にダークモードの定義が**ない**（`prefers`/`dark` は 0 件）。コンポーネントは `bg-white` `text-solid-gray-800` を直書きしている。FR-U-21 はダークを MUST とし、§7.2 は録画の見え方にも言及している。したがってコンポーネントは**コピーせず**、意味トークン（`--bg` `--fg` `--border-strong` …）経由で書き直す。プリミティブ値（solid-gray / blue）は借りてよい |
| **キーカラー blue-900 `#0017c1`** | 再検討 | 行政サイト向けの濃い青で、彩度が高い。§7「無彩色＋アクセント 1 色」には合う。ただしダークでは `#0017c1` が背景に沈むので、ダーク用に明るい青（例: blue-300 系）を別に決める必要がある。DADS はそこを決めてくれない |
| **サイズ（Select lg 56px・本文 16px・広い余白）** | 縮める | DADS は不特定多数の市民が 1 回だけ使うフォームの基準。LCI は 1 人がキーボードで何百問も流し見る道具。一覧の Select は sm（40px）、行の高さは 48px、本文は 14–16px が適切。**ターゲットサイズ 44px はモバイルだけで守る** |
| **SearchBox** | 使わない | DADS SearchBox は「対象 select＋入力＋検索ボタン」で送信する前提。LCI は打つたびに絞り込む（`ProblemBrowser.tsx:45-60`）ので、送信ボタンは無意味な 1 ステップになる。Input に虫眼鏡アイコンを付けたもので足りる |
| **ChipLabel をフィルタのトグルに使う** | 使わない | DADS の ChipLabel は**非インタラクティブ**なラベル。トグルとして使うと、押せる/押せないの区別が崩れる。選択は Checkbox、適用中条件の表示は ChipLabel＋独立した × ボタン（aria-label「FE を解除」）にする |
| **Card** | 自作 | DADS は Card プリミティブを提供していない（`Card/component-spec.md`: 作例のみ）。カードは作例 1 の構造とフォーカスリングだけ借りる |
| **Table** | パターンのみ | DADS の Table は stories だけでコンポーネントがない。行全体をリンクにする作例（`Table.stories.tsx:1200` 付近）の考え方を採る |
| **Link の常時下線・visited の magenta** | 文中だけ | 文中のリンクは DADS どおり下線を付ける。一覧の行タイトルを全部下線にするとノイズになるので、ResourceList の「行全体が操作対象」パターンにする。`:visited` は「開いた」ことしか示さず「挑戦した」とは違うので、データ由来の状態チップを使い、visited 色は使わない |
| **Heading の装飾（左のチップ・下線ルール・肩見出し）** | 使わない | 文書サイトの章立て向けの装飾で、アプリ画面では重い。サイズと太さの段階（24/20/16 Bold）だけ借りる |
| **Noto Sans JP / Noto Sans Mono の強制** | 見送り | ローカルの Mac アプリなので、Hiragino（システム）で十分に読める。Web フォントを同梱すると数 MB 増える。Noto Sans Mono はコード用としてリガチャや字形の区別（0/O, l/1）が弱い。§7.1 の JetBrains Mono 相当を維持する |
| **Breadcrumbs を全ページに** | 階層 2 以上だけ | IA はほぼ 2 階層しかない。トップレベルに置くと「ホーム › 履歴」のような自明な 1 段が増えるだけ |
| **黒＋黄のフォーカスリング** | 採用。ただし S3 では弱める | Browse では最良の選択。ただし面接画面では録画に黄色が映り込み、§7 原則 1「静か」と衝突する。S3 では同じ形のまま無彩色（fg 色 2px）にする（担当外なので申し送り） |
| **NotificationBanner** | Browse だけ | 中断セッションの告知には適切。S3 / S4 には出さない（§7.4 通知禁止） |
| **StepNavigation** | 見た目だけ | S2 の「この練習の流れ」は状態を持たない説明。操作できるステッパーにすると、押せそうに見えて誤解を生む |
