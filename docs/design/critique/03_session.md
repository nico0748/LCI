# 03 セッション画面（S2 事前確認 / S3 面接）批評と再設計案

対象: `PreflightScreen.tsx`（`/session/new`）、`InterviewScreen.tsx`（`/session/[id]`）、`globals.css`
根拠: 04 §6.2 / §7、01 FR-C-06/07/63・§6.2 失敗モード、スクリーンショット `design/before/*`
表記: `P:123` = PreflightScreen.tsx 123 行、`I:123` = InterviewScreen.tsx 123 行、`G:12` = globals.css 12 行

前提として、このアプリで一番大事なのは 15〜45 分間「話しながら書く」ことを妨げないことです。DADS は行政サービス向けで、1 回きりの手続きを迷わず終えるための設計体系です。一方 S3 は IDE で、同じ人が何十回も使い、操作の密度が高い画面です。なので DADS からは「状態の伝え方」「失敗時の案内」「モーダルのフォーカス管理」「コントラスト基準」を取り入れ、サイズや余白はそのまま持ち込みません（§5）。

## 1. 現状の問題点（重大度順）

重大度: **P0** = 練習データを失う、または誤操作で不可逆な結果になる／**P1** = 集中や本番再現性を継続的に損なう／**P2** = 分かりにくい・一貫しない／**P3** = 磨き込み

### P0-1 終了確認の初期フォーカスが「終了する」にある
- `I:670` の `autoFocus` は破壊的なボタンに付いています。`⌘⇧E` を誤って押す、あるいは Monaco で改行しようとして Enter を押すと、モーダルにフォーカスが移った直後の Enter でそのまま終了してしまいます。終了すると録画が確定し、S4 へ遷移するため取り消せません。
- モーダルの実体は `role="dialog"` を付けただけの `div` です（`I:631`）。フォーカストラップも、背景の `inert` もありません。Esc は window リスナーで処理していますが（`I:655-661`）、Tab を押すとフォーカスが背面のヘッダやエディタへ抜けます。
- 終了処理が失敗したとき（`I:636-643`）に出るのは「もう一度」ボタンだけで、データがどこに残っているかを示しません。

### P0-2 録画が止まったことが目立たない（FR-U-06 / FR-C-07 未達）
- 録画中・停止・記録のみの 3 状態とも、8px のドットと `text-xs text-fg-muted` の 1 語で表しています（`I:499-501`）。正常時と停止時で、表示の大きさも配置も同じです。実際の画面は `interview-live-desktop-light.png` 右上の「● REC」で、注意していないと読めない大きさです。
- 警告バナー（`I:515-520`）は `text-xs` の `--warn` で、明るい背景とのコントラストは 3.57:1 です。FR-C-07 が求める「再取得を促す UI」（再接続ボタン）がなく、「閉じる」しか押せません。
- 詳細（チャンク数・未送信数）は `title` のツールチップにしかなく（`I:468`）、キーボードからは見えません。
- 無音検知（FR-C-06: RMS が閾値未満の状態が 10 秒続いたら警告）はセッション中の UI にありません。録れていない状態に終了後まで気付けません。

### P1-3 開始操作が 2 回あり、「開始」という表示が事実と違う
- S2 の「開始」（`P:380-387`）は `/api/sessions` と `/start` を POST してから遷移します（`P:186-201`）。遷移先では「問題を表示して開始」（`I:471-486`、`interview-ready-desktop-*.png`）をもう一度押す必要があります。04 §5.2 の「S2 → S3 は 1 操作（Enter）」と食い違います。
- ユーザーは 1 回目で始まったと思ってしまいます。また、ready 画面で離脱すると、`/start` 済みで中身が空のセッションが履歴に残ります（要確認: 履歴での見え方）。
- ready 画面には意味が 2 つあります。画面録画の `getDisplayMedia` に必要なユーザー操作を得ることと、リロード後に再開することです（`I:478-482`）。この 2 つが必要なのは画面録画 ON の場合と再開の場合だけです。

### P1-4 タイマーが不安を煽り、ラベルとコントラストも不十分
- `mm:ss` の秒が常に刻んでいます（`I:495-498`）。§7 原則 1 は「動くのはタイマーだけ」と認めていますが、周辺視野で 1 秒ごとに数字が変わることは、説明中の思考を何度も中断させます。実際の面接では面接官が「残り 5 分です」と口頭で伝える程度です（04 §6.2）。
- 「残り」というラベルがありません（`title` 属性のみ）。数字だけを見ても、経過時間か残り時間か判別できません。
- 残り 5 分になると `text-warn font-semibold` に変わり、さらに「残り N 分」が追加されて幅が変わります（`I:495-497`）。幅が変わるとヘッダのボタンが左へずれ、レイアウトが動きます。`--warn` #c7730a の対背景コントラストは 3.57:1（`G:15`）で、14px の文字としては WCAG AA に届きません。
- 0 秒で `finish("timeout")` が即座に走り、画面が遷移します（`I:204`）。話している途中の文が切れて保存されます。

### P1-5 ボタンに階層がなく、終了を押し間違えやすい
- 実行・提出(判定)・終了は、同じ枠線と同じ大きさです（`I:504-512`）。違いは終了の文字が赤いことだけです。終了は最も押しやすい右上の角にあり、提出のすぐ隣に置かれています。
- 「提出」という語は、取り消せない最終提出を連想させます。実際には途中で何度でも実行できるサンプル判定です（`I:341-369`）。
- 押すと「実行中…」「判定中…」にラベルが変わり、ボタン幅が変わります。そのたびにヘッダが横にずれます（`I:505, 508`）。
- `testsKind === "none"` で判定を無効にした理由が表示されません（`I:507`）。

### P1-6 ペインの比率が固定で、プレビューの幅が判定条件と合わない
- `3fr 6fr 3fr` で固定されています（`I:522`）。FR-U-04（MUST）と §7.1 の「ドラッグ可、比率保存」を満たしていません。
- 1440px 幅ではプレビューが約 360px になります。一方、判定用フレームは 800×600 の実寸で描画されます（`I:237, 591`）。候補者が見ているレイアウト（スマホ幅）と、判定が見ているレイアウト（PC 幅）が異なります。Pixiv 型の「input と button を横並び」のような要件では、これが致命的なずれになります。
- 問題ペインを折りたたむと幅 0 で完全に消え（`I:522-524`）、マウスで戻す手段がありません。「⌘B で折りたたみ」のヒントはペインの最下部にあり（`I:533`）、スクロールしないと見えません。

### P1-7 ダークモードでプレビューが白一色になる
- `bg-white`（`I:236, 581`）のため、`interview-live-desktop-dark.png` では右上の約 360×670px が純白になります。画面で最も明るい面が視界の端にあり続けるため、エディタへの集中を最も強く妨げています。中身は候補者自身の HTML なので、強制的にダーク化すべきではありません。ただし、枠も見出しもないため「白い穴」に見えています。

### P1-8 フォローアップの質問が読めない
- フッターに `truncate max-w-[50%]` で 1 行だけ表示しています（`I:621-626`）。質問が長いと途中で切れます。答えるべき質問が全文読めないのは、機能として成立していません。
- `aria-live` がないため、スクリーンリーダーは新しい質問に気付けません。「既読」ボタン（`I:624`）はマウス操作が前提です。
- 質問の表示位置が「ライブ字幕: 未対応」と同じ淡い帯の中です。04 §6.2 が想定する「右下に 1 件、既読まで残る」と比べても控えめすぎます。

### P2-9 判定と通知の表示が、内容を押し下げて残り続ける
- `notice` と `judgeSummary` は、右ペインの上部に条件付きで差し込まれます（`I:577-578`）。表示されるたびにプレビューやコンソールが下へずれ、消すこともできません。「判定中…」の後に結果が出ると、行の高さも変わります。
- Docker が未起動であることは S2 で分かっています（`P:369-373`）。それなのに S3 では「実行」を押して初めて「実行環境が未起動です」と知らされます（`I:303, 307`）。
- 結果の文「判定を記録しました（3 / 5 件 通過）。詳細は終了後の振り返りで確認できます。」（`I:321, 356`）は長く、1 行に収まりません。

### P2-10 中身のない領域と常設ショートカットがノイズになっている
- フッター左には「ライブ字幕: 未対応」が常に表示されています（`I:620`）。S2 でも、未対応のライブ字幕をチェックボックスとして選べます（`P:345-348`）。CLAUDE.md の「メタデータだけで宣言しない」と同じ理由で、機能がないものを UI に出すべきではありません。
- フッター右にはショートカット一覧が常に表示されています（`I:627`、`interview-live-*` 下端）。覚えた後は毎回読まれないノイズになります。

### P2-11 Monaco が LCI の配色と合っていない
- 標準の `vs` / `vs-dark` を使っています（`I:63-69, 558`）。明るいテーマでは行番号が青緑（#237893）で、アプリの無彩色＋アクセント 1 色という方針から外れています。現在行のハイライトは枠線として描かれ、選択範囲と見間違えます（`interview-live-desktop-light.png` 1 行目）。
- 暗いテーマでは、問題ペインとタブバー（`--bg` #141415）、エディタ（#1e1e1e）、ヘッダ（`--bg-elev` #1d1d1f）の 3 種類の黒が並び、境界が濁ります（`interview-live-desktop-dark.png`）。
- `fontFamily` を指定していないため、`--font-mono` が使われていません。横スクロールバーが太く目立ちます（light の y≈860 の灰色の帯）。

### P2-12 問題文が読みにくい
- 「問題文」「制約」の見出しが `text-xs text-fg-muted`（`I:525, 529`）で、本文より弱く表示されます。読み返すときに区切りを見つけにくくなっています。
- 幅 360px のため、コードブロックが横に切れます（`interview-live-*` の「Consectetur adipi」）。URL のインラインコードも途中で折り返します。
- 本文は 14px で、行間は `leading-relaxed`（1.625）です。この密度は悪くありませんが、1 行が全角で約 22 字しか入らず、段落が縦に長くなります。

### P2-13 事前確認の失敗時の案内が弱い
- 権限が拒否されたとき、ブラウザやエラーのメッセージがそのまま出るだけです（`P:278-290`）。01 §6.2 が求める「システム設定への導線」（Chrome のサイト設定、macOS のプライバシーとセキュリティ）がありません。
- Docker の状態はテキスト 1 行です。再確認ボタンがなく、`unknown` のときは「実行環境の状態 API がまだありません」という開発者向けの文言が出ます（`P:82, 373`）。
- マイクのメーター（`P:272-277`）には目安がありません。どれくらいの音量なら十分なのか、声が届いたかどうかが分かりません。倍率 ×6（`P:153`）も根拠のない値です。
- デバイスの選択欄は、ストリームを取得できた後にしか出ません（`P:291`）。既定のマイクで失敗したときに、別のマイクを選べません。
- 同意画面（`P:224-251`）には「理解して続ける」しかなく、戻る手段や中止する手段がありません。S2 全体にも問題一覧へ戻るリンクがありません（`(session)` に layout がない）。
- 言語は S2 で確定する仕様ですが（FR-U-03）、表示しかしておらず変更できません（`P:260`）。

### P3-14 アクセシビリティ
- コントラストが不足している箇所（計算値）:
  - `--warn` は明るい背景で 3.33〜3.57:1、`--danger` は暗い背景で 3.27:1 です（終了ボタンの文字 `I:510`）。
  - ダークテーマでは `--warn`、`--danger`、`--rec` が再定義されていません（`G:23-42`）。
  - `--border` は 1.29:1 で、select・textarea・checkbox の外枠に使われています（`P:295`、`I:597`）。WCAG 1.4.11（3:1）を満たしません。
- キーボード操作の問題:
  - `⌘⌥←/→`（`I:411, 443`）は、Mac の Chrome でタブ切替に割り当てられています。ページ側で横取りできない可能性があります（要確認）。仕様書の `Cmd+1`（04 §6.2）も Chrome がタブ 1 への移動に予約しています。
  - Monaco の中では Tab がインデントに使われるため、エディタから他のペインへキーボードで出る手段がありません（`Ctrl+M` を知っている人だけが出られます）。
  - ファイルタブは `role="tab"` ですが、矢印キーで移動できず、`aria-controls` も `tabpanel` もありません（`I:538-550`）。
  - タイマーに `role="timer"` がありません。DOM の順序は「ヘッダ → 問題 → エディタ」で、§7.3 が定めるフォーカス順「問題→エディタ→プレビュー→終了」と異なります。

## 2. 事前確認（S2）の再設計

### 2.1 判断: StepNavigation のウィザードではなく「1 画面＋準備状況リスト」にする
DADS の StepNavigation（`StepNavigation/component-spec.md`）は、前の入力が次の入力の前提になる、順番のある手続き向けです。S2 の確認項目はほとんど互いに独立していて、自動で並行に進められます。カメラ・マイク・Docker・モードには依存関係がありません。5 段階のウィザードにすると、毎回 4 回余計にクリックすることになり、「Enter 1 回で開始」（FR-U-03）と両立しません。2 回目以降、全部 OK の人にとってはただの障害物です。

- **同意だけは独立したゲートにする**（初回のみ、FR-C-63）。これはステップではなく前提条件です。ステップ表示も出しません。
- 確認項目は、DADS の「状態をアイコン＋文言で示し、色だけに頼らない」という考え方を借りて、**準備状況リスト**として縦に並べます。ProgressIndicator（スピナー）は回転アニメーションを使うので採用しません（`ProgressIndicator/keyframes.css`）。「確認中」はテキストと静止アイコンで表します。
- S3 の ready ゲート（P1-3）は原則なくし、S2 の Enter 1 回で問題表示・タイマー・録画を同時に始めます。ready ゲートを残すのは (a) 画面録画 ON の場合（ボタンを「画面共有を選んで開始」にする）と (b) 再開の場合だけです。セッションの作成（POST）も開始の瞬間にまとめ、空のセッションが残らないようにします。
  - 要確認: Next の `router.push` は同じドキュメント内の遷移なので、クリックによる user activation が S3 側の `getDisplayMedia` まで残るかもしれません。残るなら (a) も不要になります。

### 2.3 項目ごとの見せ方
- **準備状況リスト**: 各行は「状態アイコン（✓ / ! / × / ◌ 確認中）＋項目名＋検出内容＋操作」の形にします。`role="list"` とし、状態が変わったときは `aria-live="polite"` で 1 回だけ読み上げます。開始を止めるのは「×」の行だけです。「!」は開始ボタンの下に 1 行で注記します（Docker がなくても練習できる、という現状の正しい方針を見える形にします）。
- **カメラプレビュー**: プレビューは鏡像で表示し、録画は反転しないことを注記します。カメラ OFF のときは、プレビューの枠を残したまま「音声のみで記録します」と表示し、レイアウトが動かないようにします。
- **マイクレベル**: 12 分割の静止セグメントにし、「目安」線を 1 本引きます。目安を超える音量が 1 秒続いたら「✓ 声を検出しました」に変え、リストのマイク行を ✓ にします。滑らかに動くバーは不要です（150ms 更新のままでよい）。この画面ではメーターの動きを許容し、S3 には持ち込みません。
- **Docker**: `not_running` と `missing` で文言を分けます。「起動方法 ▸」は DADS Disclosure で開閉し、「Docker Desktop を起動 → [再確認]」の 2 手順を示します。`unknown` では開発者向けの文言を出さず、「確認できませんでした（実行・判定が使えない可能性があります）」とします。
- **権限拒否**: DADS NotificationBanner の error（standard）を S2 に限って使います。本文は「Chrome のアドレスバー左のアイコン → カメラ・マイクを許可」「macOS 設定 → プライバシーとセキュリティ → カメラ／マイク → Chrome」の 2 手順にし、[もう一度確認] と [録画なしで続行（編集ログのみ）] を並べます。デバイスの選択欄は、失敗時にも出します。
- **記録オプション**: 即座に反映されるカメラは DADS Switch にします（DADS の使い分けでは、即時に効くものは Switch）。開始時に効く画面録画は Checkbox のままでもかまいませんが、見た目は統一して Switch にそろえます。ライブ字幕は実装されるまで項目ごと削除します。
- **言語**: `HTML/JS ▾` をメタ行に置き、`languages` が 2 つ以上あるときだけ変更できるようにします（FR-U-03）。
- **同意画面**: 本文を「記録するもの／保存場所／外部に送るもの・送らないもの」の 3 見出しに分けた Dl にします。[理解して続ける]（solid）と [問題一覧に戻る]（text）を置きます。チェックボックスで同意させる形にはしません。個人がローカルで使うアプリでは、二重の確認は儀式でしかないためです。

### 3.2 レイアウト
- **ヘッダ 40px は維持**します。中のボタンは見た目 28px（DADS Button の xs 相当）にし、44px のタップ領域を作る擬似要素は付けません（§5）。並び順は「問題名（左、truncate）｜録画状態｜残り時間｜区切り｜実行・判定｜余白 24px｜終了…」です。終了は距離と区切りで実行系から離します。
- **初期比率**:
  - web 問題: 問題 24% / エディタ 44% / 右 32%（1440px で 346/634/460px）
  - stdio・unit 問題: 問題 26% / エディタ 52% / 右 22%
  - 区切りはドラッグとキーボードで動かせるようにし、最小幅は問題 240px・エディタ 480px・右 280px とします。比率は `localStorage` に問題の種類ごとに保存します（キャッシュ用途なので try/catch で包みます）。
- **問題ペインの折りたたみ**: 折りたたんだら幅 0 ではなく、32px のレールを残します。縦書きの「問題」と ⌘B を表示し、クリックでも開けるようにします。開閉はアニメーションさせません。
- **1280px 未満**（FR-U-24）: 右ペインをエディタ上部のタブ（エディタ｜プレビュー）にまとめ、2 ペインにします。

### 3.3 タイマー
- **表示**: 「残り 19 分」のように、ラベル付きで分単位にします。値は切り上げです。秒は出しません。そのため画面上の動きは 1 分に 1 回まで減ります。残り 5 分からは `残り 4:59` の秒表示に切り替えます。ここで初めて秒が動き出すこと自体が、強すぎない合図になります。
- **残り時間と経過時間**: 既定は残り時間です。本番で配分を判断する材料になるためです。タイマーをクリックすると経過時間（`経過 0:42`）と切り替えられ、設定は保存します。経過表示を好む人もいますが、既定にはしません。
- **5 分前**: 色は `--warn-fg`（明 #9a5a00 = 5.47:1、暗 #e0a040 = 7.43:1）にし、太さは変えません。左に 3px の縦線を付けます。色・テキスト・形の 3 つで示し、赤は使いません（赤は「録画停止」と「終了」のために取っておきます）。
  - 幅は `min-width: 9ch` で固定し、ずれないようにします。
  - 1 分前のチャイム（`chime.ts`）は現状のままにし、S2 で ON/OFF を選べるようにします（FR-U-22）。
- **0 分**: 入力をロックし、録画は 5 秒延長します（最後の 1 文を切らないため）。DADS ModalDialog で「時間になりました。保存しています」と表示します。猶予は本番より甘くなりますが、録画で文が途中で切れると振り返りで聞き取れないため、こちらを優先します。
- `role="timer"` を付け、`aria-live="off"` にします。残り 5 分と 1 分になったときだけ、別の live region で 1 回読み上げます。

### 3.4 録画状態（REC）
| 状態 | 表示 | 補足 |
|---|---|---|
| 録画中 | `● 録画中`（静止した赤ドット 8px、文字は `--fg-muted`） | 点滅させない |
| 記録のみ | `○ 録画なし` | 中が空のドット＋灰色。S2 でユーザーが選んだ状態なので警告しない |
| 停止・失敗 | ヘッダ直下に 32px の警告帯「録画が止まっています（マイクが切断されました）。編集ログは記録を続けています。[再接続] [詳細]」 | 帯の色は `--danger`、文字は 4.5:1 以上。レイアウトが動いても目立つことを優先する（FR-U-06）。再接続できたら帯を消し、ヘッダに戻す |
| 無音 10 秒 | `● 録画中 · 音声が届いていません`（文字を `--warn-fg` に） | FR-C-06。帯は出さない（考えていて黙っているだけの可能性があるため） |

詳細（チャンク数・未送信数・トラック）は、`● 録画中` をクリックするか ⌘K R で小さなポップオーバーに出します。ツールチップ専用にはしません。

### 3.5 ボタンの階層
- **実行** と **判定**: DADS の outline 相当で、28px です。ラベルの横にショートカットを `kbd` で薄く表示し（`実行 ⌘↵`）、フッターの常設一覧の代わりにします。処理中もラベルは変えず、`aria-busy` と静止した「…」だけを付けて幅を固定します。
- **「提出(判定)」→「判定」** に改名し、ツールチップを「公開サンプルで判定（何度でも可）」にします。判定がない問題ではボタンを置かず、「この問題には判定がありません」を右ペインの状態行に出します。
- **Docker が使えない場合**: S2 の結果を受け取り、実行と判定を開始時点から `aria-disabled` にします。理由は状態行に「実行環境なし（事前確認で検出）」と出します。押してから失敗させるのはやめます。
- **終了…**: text 型のボタンで、色は無彩色です（赤にしません）。「…」で確認があることを示します。画面上の赤は録画停止だけに使い、意味を一意に保ちます。
- ヘッダに solid（塗り）のボタンは置きません。セッション中の主役はエディタです。

### 3.6 判定結果の控えめな通知
右ペインの最下部に、**28px で高さ固定の状態行**を置きます。中身だけを差し替え、新しい行は差し込みません（レイアウトシフトをなくすため）。

`判定 12:34　サンプル 3 / 5 通過　詳細は振り返りで` ／ 判定中は `判定中…`（静止テキスト）／ 失敗時は `判定できませんでした: 実行環境なし`

- 合否で色を変えません。緑・赤・アイコンは使わず、無彩色の文字だけにします（04 §7 原則 2: セッション中に採点しない）。件数は本番の「サンプルテストを流す」行為と同じ程度の情報なので出します。S2 に「判定結果: 件数を表示 / 実行したことだけ記録」の設定を用意します。
- `aria-live="polite"` で 1 回だけ読み上げます。トーストやバッジは使いません。

### 3.7 プレビュー / コンソール
- 右ペインは compact タブ「プレビュー｜コンソール N｜通信 N」にします（web のとき）。件数は静止した数字だけを出し、新着を強調しません。
- 「通信」タブは表で「時刻・URL（クエリ）・状態（完了/中断/ブロック）・所要」を並べます。fe-0001 のような「サーバーに優しい」問題では、リクエスト数が説明の材料になるので、`I:583` の 1 行集計を格上げします。
- **プレビューの幅**: 既定は「判定と同じ 800px の実寸を幅に合わせて縮小表示」にし（静的な transform scale。アニメーションなし）、「実寸」に切り替えられるようにします。こうすると判定とのずれ（P1-6）がなくなります。
- **ダークモード**: iframe の中身は変えません。周りに 12px の `--bg` の余白と 1px の枠を付けて「紙」として見せ、白い穴に見える状態を和らげます。注記は付けません（すぐ慣れるため）。
- stdio 問題では「入力」（ラベル付き textarea、高さ可変）と「出力」を縦に並べます。出力の先頭の `AC · exit 0 · 120ms` は「正常終了 · 120ms」のように日本語化し、終了コードが 0 でないときだけ数字を出します。

### 3.8 フォローアップと字幕ストリップ
- **フッター（ストリップ）の役割を、面接官の質問を表示する場所として決め直します。**
  - silent モードでライブ字幕も未実装なら、フッターを出しません（高さ 0）。
  - followup モードでは 28px にします。質問が来たら最大 48px（2 行）に広げ、全文を表示します。
  - エディタの上ではなく下で広げるので、カーソル付近の行は動きません。
- 質問は「面接官」というラベルと本文だけにします。アイコン・色・動きは付けません。`role="status"` と `aria-live="polite"` を付けます。次の質問が来るまで残し、既読ボタンはなくします。消すのは ⌘K . です（任意）。それまでの質問は ⌘K Q で一覧できます。
- ライブ字幕を実装したら、同じ帯の左に「直近 1 文、淡色、1 行」で出し、面接官の質問が出ている間は質問を優先します（字幕は文字起こしの状態表示に戻します）。

### 3.9 終了確認を DADS ModalDialog に
- ネイティブの `<dialog>` と `showModal()` にします。フォーカストラップと背景の inert はブラウザに任せます。**初期フォーカスは見出し**にします（DADS の useModalDialog の仕様どおり）。そのため Enter を押しても何も起きません。Esc でキャンセルするのは DADS の `cancel` イベント処理をそのまま使います。

```
┌ セッションを終了しますか？ ──────────── [× 閉じる] ┐
│ 残り 7 分 12 秒あります。                              │
│ 終了すると録画を保存し、振り返り画面へ移動します。       │
│ 終了したセッションは再開できません。                     │
│                                                       │
│                    [続ける]   [終了して保存]            │
└───────────────────────────────────────────────────────┘
```
- [終了して保存] は solid にします（このダイアログの主操作だからです）。続けるは outline で Esc と同じ動作です。キーボードでは Tab で終了ボタンへ移ってから Enter を押す必要があり、誤操作に 2 段の壁ができます。
- 保存中は同じダイアログの本文を「録画と記録を保存しています…（閉じないでください）」に差し替えます。スピナーは使いません。失敗時は error の NotificationBanner をダイアログの中に出し、「データは `data/sessions/<id>/` に残っています」と [もう一度] [保存せずに振り返りへ] を表示します。

## 5. DADS をそのまま当てはめない箇所

1. **ターゲットサイズ**: DADS Button は md で 48px、lg で 56px あり、sm と xs にも高さ 44px の当たり判定を作る擬似要素（`Button.tsx` の `after:h-[44px]`）があります。40px のヘッダに 28px のボタンを並べると、この当たり判定が隣のボタンと重なり、押したつもりのないボタンが反応します。S3 は見た目 28px・当たり判定 28px にし、間隔を 8px 以上空けて WCAG 2.5.8（24px）を満たすことにします。S2 と同意画面では、DADS の md/lg をそのまま使います。
2. **フォーカスリング**: DADS は黒 4px の outline＋黄色の ring です。S2 とモーダルではそのまま使います。S3 では、エディタ内のフォーカスはカーソルそのものです。ペイン単位のフォーカスは 2px のアクセント色の inset 線にします。常に黄色い枠があると、§7 原則 1（色は無彩色＋アクセント 1 色）と衝突するためです。ボタンにキーボードでフォーカスしたときは、DADS のリングを使います。
3. **NotificationBanner の大きさ**: padding 24〜32px、アイコン 36px、見出し 20px Bold です（`NotificationBanner.tsx`）。S3 で使うとエディタが 120px 以上押し下げられます。S3 では color-chip の「左の帯で種類を示す」という文法だけを借り、32px の 1 行の帯にします。
4. **ProgressIndicator**: スピナーも linear の不確定表示もアニメーションします（`keyframes.css`）。S3 では全面禁止にし、静止テキストで代用します。S4（保存・評価待ち）なら使えます。
5. **StepNavigation**: §2.1 で述べたとおり、手順に依存関係がないので使いません。順番のない確認作業をステップに見せると、「全部終えないと進めない」という誤解と余計なクリックを生みます。
6. **配色**: DADS のトークンにはダークモードの定義がなく、キーカラーの blue-900（#0017c1）は暗い背景では沈みます。LCI はライトとダークの両方を自前で持ち、DADS からは semantic（success/error/warning）の明度設計と、コントラストを 4.5:1 / 3:1 にする規律を借ります。DADS の警告色の黄色は、ダークで不安を煽る彩度になるため、警告には琥珀色（#e0a040）を使います。
7. **本文の文字サイズ**: DADS の標準は 16px・行間 1.7 です。問題ペインに当てはめると、1 行が全角約 20 字になり、読み返す量が増えます。問題文は 14px・行間 1.7（行間だけ DADS に合わせる）にし、S7 で 16px も選べるようにします。S2 と同意画面は 16px です。
8. **Tab の見た目**: DADS Tab は大きなパネル切替向けです。エディタのファイルタブは IDE の慣習（28px、等幅、閉じるボタンなし）に従い、借りるのは ARIA と矢印キーの操作だけです。
9. **ModalDialog の閉じるボタン**: DADS の「× 閉じる」はそのまま使います。ただし時間切れの保存中は、閉じるボタンも Esc も無効にします（保存を中断させないため。DADS の `onRequestClose` で `preventDefault` します）。
